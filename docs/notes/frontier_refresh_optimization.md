# 前沿点持续更新机制 - A*失败恢复优化

## 问题描述

之前的实现中，当A*路径规划失败（无法到达某个前沿点）时，系统可能会：
- 进入冷却期，暂停前沿刷新
- 反复尝试到达同一个无法到达的前沿点
- 探索进程卡住，无法继续

## 解决方案

### 1. 定期全量刷新机制

**实现位置**: `frontier_explorer.py`

```python
# 初始化时添加刷新计数器
self._incremental_update_count = 0
self._full_refresh_interval = 10  # 默认每10次增量更新后全量刷新
```

**工作原理**:
- 每次增量更新后计数器+1
- 达到阈值时自动触发全量刷新
- 重置计数器，防止累积误差

**可配置接口**:
```python
explorer.set_refresh_interval(5)  # 设置刷新间隔为5次
```

### 2. A*失败时强制刷新

**实现位置**: `main.py` 第2518-2553行

**处理流程**:
1. **检测A*失败**: `planned_path is None`
2. **强制全量刷新**: 调用 `explorer.force_full_refresh()`
3. **重新搜索前沿**: 使用全局前沿检测
4. **降级策略**: 如果仍失败，降低安全距离重试
5. **保持探索**: 即使失败也不卡住，继续DWA探索

```python
# A*失败处理逻辑
if planned_path is None:
    print(f"[A*失败] 无法到达前沿点 {target_cell_latest}，强制刷新前沿并重新搜索")
    
    # 1. 强制全量刷新
    explorer.force_full_refresh()
    
    # 2. 重新搜索
    retry_frontier, retry_path = explorer.find_nearest_frontier(occupancy, (rx_idx, ry_idx))
    
    if retry_frontier is not None and retry_path:
        # 使用新找到的前沿点
        target_cell_latest = retry_frontier
        planned_path = list(retry_path)
    else:
        # 3. 降级策略：降低安全距离
        relaxed_safety = max(1.0, safety_cells * 0.5)
        planned_path, _ = plan_path_with_safety(...)
```

### 3. 手动触发刷新接口

**新增方法**:
```python
def force_full_refresh(self) -> None:
    """强制在下次调用时执行全量前沿刷新"""
    self._incremental_update_count = self._full_refresh_interval
    print("[Frontier] 已设置强制全量刷新标志")
```

**使用场景**:
- A*路径规划失败
- 检测到地图有重大变化
- 怀疑增量更新累积误差
- 手动触发完整重扫描

## 错误处理

### 场景1: A*完全失败
**处理**: 降低安全距离重试，允许路径穿过少量未知区域

### 场景2: 无可达前沿
**处理**: 切换到探索完成模式，SLAM转为定位专用

### 场景3: 前沿集合为空
**处理**: 全局前沿检测作为回退策略
